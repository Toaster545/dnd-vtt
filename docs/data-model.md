# Data model: every SQLite table after migrations v001–v036, their key columns and relationships, and the shape of the JSON `data` blobs.

Last updated: 2026-10-28 (commit 00cb49a)

The schema exists only as the sequence of migration files in `dnd_vtt_backend/src/common/migrations/`; the tables below are the state after all of them have run (`user_version` 36). The migration mechanism (runner, `PRAGMA user_version` stamping, the missing v022) is described once in [architecture/storage.md](architecture/storage.md#migrations) and not repeated here. Only columns that matter for understanding the model are listed; the file named in each section has the full column list.

Conventions that hold for every table:

- Primary keys are `TEXT` (UUID strings generated in the services).
- Timestamps are `TEXT`. Most use `DEFAULT (datetime('now'))`; some are written by services as ISO strings.
- Booleans are `INTEGER` 0/1 (`visible_to_players`, `enabled`, `edit_unlocked`, ...). The API returns them raw, see `UpsertTokenDto` in [api/maps.md](api/maps.md).
- JSON is stored in `TEXT` columns (`data`, `monsters`, `character_ids`, `hidden_cells`, `walls`) and parsed with `DatabaseService.parseJson`.
- Foreign keys are enforced (`PRAGMA foreign_keys = ON` in `runMigrations`).

Sources: `dnd_vtt_backend/src/common/migrations/index.ts` (`MIGRATIONS`), `dnd_vtt_backend/src/common/database.service.ts`.

## Entity overview

```
profiles ─┬─< characters ─┬─< companions ─< companion_turns >─ encounters
          │               ├─< inventory_instances, inventory_requests
          │               └─< wiki_pages (character notes)
          ├─< campaigns ─┬─< campaign_members >─ characters (copy, source)
          │              ├─< sessions ─< encounters ─< encounter_levels >─ battle_maps
          │              ├─< wiki_pages ─< wiki_page_links / wiki_page_versions
          │              └─< campaign_visits
          ├─< auth_sessions
          └─< custom_monsters / custom_items / custom_spells / item_image_overrides

battle_maps ─┬─< map_tokens ─< map_lights
             ├─ map_fog (1:1)
             └─ map_lighting (1:1)
```

`battle_maps.campaign_id` has no foreign key (default `'default'`, see below).

## Accounts and sessions

### `profiles` (v001)

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | |
| `email` | TEXT UNIQUE NOT NULL | |
| `username` | TEXT UNIQUE NOT NULL | |
| `password_hash` | TEXT NOT NULL | bcrypt, see [architecture/auth.md](architecture/auth.md#tokens) |
| `role` | TEXT NOT NULL | `CHECK(role IN ('admin','player'))`, default `'player'` |
| `created_at` | TEXT | |

Referenced with `ON DELETE CASCADE` by `characters`, `campaigns`, `campaign_members`, `campaign_visits`, `sessions`, `encounters`, `auth_sessions`, the `custom_*` tables, `item_image_overrides` and `wiki_pages.author_id` / `owner_id`.

### `auth_sessions` (v021)

Refresh-token sessions. Columns: `id` PK, `user_id` → `profiles` (CASCADE), `token_hash` (SHA-256 of the refresh token), `client_type` (`CHECK IN ('web','native')`), `expires_at`, `revoked_at` (nullable), `created_at`, `last_used_at`. Indexes: `idx_auth_sessions_user_id`, `idx_auth_sessions_expires_at`. Behaviour: [architecture/auth.md](architecture/auth.md#auth-endpoints-and-refresh-flow).

Sources: `v001.ts`, `v021.ts`.

## Campaigns

### `campaigns` (v007, v009, v021)

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | |
| `dm_id` | TEXT NOT NULL | → `profiles` (CASCADE). The owner; all DM checks compare against it |
| `name`, `description` | TEXT | `description` default `''` |
| `join_code` | TEXT NOT NULL UNIQUE | generated by `src/common/join-code.util.ts` |
| `data` | TEXT NOT NULL | JSON blob, see [Campaign `data` blob](#campaign-data-blob) |
| `background_url` | TEXT | v009 |
| `current_session_id` | TEXT | v021, no foreign key; set by `PATCH /campaigns/:id/current-session` |
| `created_at`, `updated_at` | TEXT | |

v007 also created a "Legacy Campaign" per DM who already had sessions, and assigned those sessions to it.

### `campaign_members` (v007, v011, v014, v015)

One row per player joining a campaign with a character.

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | |
| `campaign_id` | TEXT NOT NULL | → `campaigns` (CASCADE) |
| `user_id` | TEXT NOT NULL | → `profiles` (CASCADE) |
| `character_id` | TEXT NOT NULL | → `characters` (CASCADE). The campaign **copy** the player plays |
| `source_character_id` | TEXT | → `characters` (SET NULL). The player's original character |
| `status` | TEXT NOT NULL | `CHECK IN ('active','removed')`, default `'active'` |
| `joined_at` | TEXT | |
| `edit_unlocked` | INTEGER NOT NULL | v011, default 0. DM grants full edit of the copy |
| `show_race_class` | INTEGER NOT NULL | v014, default 0. The player's choice to show race/class to the rest of the party (the DM always sees it) |
| `visible_to_party` | INTEGER NOT NULL | v015, default 0. Set by the DM; non-DM members only see roster entries that are visible or their own (`CampaignsService.findOne`) |

Unique partial index `idx_campaign_members_active` on `(campaign_id, user_id) WHERE status = 'active'`: one active membership per user per campaign; removed rows are kept as history.

### `campaign_visits` (v016)

`(campaign_id, user_id)` composite PK (both CASCADE), `visited_at` TEXT. Upserted when a user loads a campaign; used to order the campaign list by recent use.

Sources: `v007.ts`, `v009.ts`, `v011.ts`, `v014.ts`, `v015.ts`, `v016.ts`, `v021.ts`; `dnd_vtt_backend/src/campaigns/campaign-data.ts`.

## Sessions and encounters

### `sessions` (v001, v007, v009)

Game sessions inside a campaign. Columns: `id`, `name`, `description` (default `''`), `dm_id` (→ `profiles`, CASCADE), `campaign_id` (v007, → `campaigns`, CASCADE), `visible_to_players` (v007, default 0), `background_url` (v009), `created_at`.

### `encounters` (v003, v005, v007, v010)

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | |
| `dm_id` | TEXT NOT NULL | → `profiles` (CASCADE) |
| `session_id` | TEXT | → `sessions` (SET NULL) |
| `name` | TEXT NOT NULL | |
| `map_id` | TEXT | → `battle_maps` (SET NULL). The entry level (position 0), see `encounter_levels` |
| `monsters` | TEXT NOT NULL | JSON array, default `'[]'` |
| `character_ids` | TEXT NOT NULL | JSON array, default `'[]'` |
| `status` | TEXT NOT NULL | `CHECK IN ('draft','active','ended')`, default `'draft'` |
| `join_code` | TEXT | v005 |
| `visible_to_players` | INTEGER NOT NULL | v007, default 0 |
| `summary` | TEXT NOT NULL | v007, default `''` |
| `current_turn_token_id` | TEXT | v010, → `map_tokens` (SET NULL) |
| `round_number` | INTEGER NOT NULL | v010, default 1 |
| `created_at`, `updated_at` | TEXT | |

### `encounter_levels` (v027, v032)

Ordered maps (dungeon floors) of an encounter. `(encounter_id → encounters CASCADE, map_id → battle_maps CASCADE)` composite PK, `position` INTEGER, `name` TEXT (v032, nullable; a level's own name, never renames the map). Index `idx_encounter_levels_map`. v027 back-filled position 0 from `encounters.map_id`.

### `encounter_player_levels` (v028)

DM-chosen level per player character. `(encounter_id → encounters CASCADE, character_id → characters CASCADE)` composite PK, `map_id` → `battle_maps` (CASCADE).

Sources: `v001.ts`, `v003.ts`, `v005.ts`, `v007.ts`, `v009.ts`, `v010.ts`, `v027.ts`, `v028.ts`, `v032.ts`.

### `map_fog` (v012, v013)

One row per map: `map_id` PK → `battle_maps` (CASCADE), `enabled` INTEGER default 0, `hidden_cells` TEXT JSON array default `'[]'` (renamed from `revealed_cells` in v013).

### `map_lighting` (v018, v026, v033)

One row per map: `map_id` PK → `battle_maps` (CASCADE), `enabled` default 0, `walls` TEXT JSON default `'[]'` (v026), `ambient_level` INTEGER default 0 and `ambient_color` TEXT default `'#0a0a14'` (v033).

### `map_lights` (v018)

`id` PK, `map_id` → `battle_maps` (CASCADE), `token_id` → `map_tokens` (CASCADE; set for a light carried by a token, in which case `x`/`y` are null), `x`, `y` REAL, `bright_radius_ft` and `dim_radius_ft` INTEGER (default 20), `color` (default `'#ffa542'`), `enabled` (default 1), `label` (default `'Torch'`), `created_at`. Indexes on `map_id` and `token_id`.

## Characters

### `characters` (v001 → rebuilt in v002, v007, v021)

v002 replaced the original wide table with one that keeps a few queryable columns and puts everything else in a JSON blob, copying existing rows across.

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | |
| `user_id` | TEXT NOT NULL | → `profiles` (CASCADE). The owner |
| `name`, `race`, `class` | TEXT | `race`/`class` default `''` |
| `level` | INTEGER NOT NULL | default 1 |
| `data` | TEXT NOT NULL | JSON blob, see [Character `data` blob](#character-data-blob) |
| `campaign_id` | TEXT | v007, → `campaigns` (SET NULL). Non-null marks a **campaign copy**; null is a personal character |
| `creation_status` | TEXT NOT NULL | v021, `CHECK IN ('draft','complete')`, default `'complete'` |
| `draft_step` | INTEGER NOT NULL | v021, default 0 |
| `created_at`, `updated_at` | TEXT | |

### `inventory_instances` and `inventory_requests` (v035)

Individual item instances (needed for magic items, replicas and attunement). `inventory_instances`: `id` PK, `holder_id` → `characters` (SET NULL), `creator_id` → `characters` (CASCADE), `attuned_to` → `characters` (SET NULL), `data` TEXT JSON (an `EquipmentEntryData`); indexes `inventory_holder`, `inventory_creator`. `inventory_requests`: composite PK `(character_id → characters CASCADE, request_id)`; stores Long Rest `requestId` values so retries are idempotent (`CompleteRestDto`). v035 converted every character's `equipment` into instance rows, wrote `inventory_version = 1` into the blob, and took a `VACUUM INTO` backup first (see [architecture/storage.md](architecture/storage.md#migrations)).

### `companions` and `companion_turns` (v034)

`companions`: `id` PK, `character_id` → `characters` (CASCADE), `kind` TEXT, `data` TEXT JSON, timestamps, `UNIQUE(character_id, kind)`. `companion_turns`: composite PK `(encounter_id → encounters CASCADE, companion_id → companions CASCADE)`, `data` TEXT JSON default `'{}'` (per-encounter turn state). Rules code: `dnd_vtt_backend/src/companions/companion-rules.ts`.

Sources: `v001.ts`, `v002.ts`, `v007.ts`, `v021.ts`, `v034.ts`, `v035.ts`; `dnd_vtt_backend/src/characters/character-repository.ts` (`CHARACTER_COLUMN_KEYS`).

## Wiki

### `wiki_pages` (v023, v036)

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PK | |
| `campaign_id` | TEXT NOT NULL | → `campaigns` (CASCADE) |
| `title`, `slug` | TEXT NOT NULL | unique index `idx_wiki_pages_slug` on `(campaign_id, slug)` |
| `folder` | TEXT NOT NULL | path string, `''` = root |
| `body` | TEXT NOT NULL | markdown with `[[wikilinks]]` |
| `visibility` | TEXT NOT NULL | `CHECK IN ('shared','dm_only')`, default `'shared'` |
| `author_id` | TEXT NOT NULL | → `profiles` (CASCADE) |
| `updated_by` | TEXT | → `profiles` (SET NULL) |
| `owner_id` | TEXT | v036, → `profiles` (CASCADE). Page visible to that user only |
| `character_id` | TEXT | v036, → `characters` (CASCADE). The character's notes page; unique partial index `idx_wiki_pages_character` |
| `created_at`, `updated_at` | TEXT | `updated_at` is the optimistic-concurrency token |

### Satellite tables (v023)

- `wiki_page_links`: PK `(source_page_id → wiki_pages CASCADE, target_slug)`, `target_page_id` → `wiki_pages` (SET NULL; null is an unresolved link). Rebuilt on every save.
- `wiki_page_versions`: `id` PK, `page_id` → `wiki_pages` (CASCADE), `title`, `folder`, `body`, `editor_id` → `profiles` (SET NULL), `created_at`. A snapshot per write.
- `wiki_pages_fts`: FTS5 virtual table (`page_id` and `campaign_id` unindexed, `title`, `body`, tokenizer `porter unicode61`). It has no foreign keys; `WikiService` keeps it in sync by hand.

v023 also drops the leftover `oidc_payloads` and `wiki_campaign_links` tables (see storage doc). v024 dropped the earlier `notes` table (created in v007) and its index.

Sources: `v023.ts`, `v024.ts`, `v036.ts`; `dnd_vtt_backend/src/wiki/wiki.service.ts`.

## Homebrew content

`custom_monsters`, `custom_items`, `custom_spells` (v017) share one shape: `id` PK, `created_by` → `profiles` (CASCADE), `name`, `data` TEXT JSON (same shape as the static content files, with `data.index = 'custom:<id>'`), `created_at`, `updated_at`; each has an index on `created_by`. Libraries are per creating user.

`item_image_overrides` (v025): PK `(item_index, created_by → profiles CASCADE)`, `image_url`, `updated_at`. Lets a DM swap the picture of an official item without copying it. Behaviour: [architecture/content.md](architecture/content.md#homebrew-custom-content).

Sources: `v017.ts`, `v025.ts`, `dnd_vtt_backend/src/content/content.service.ts` (`CUSTOM_TABLE`).

## Character `data` blob

`characters.data` is a JSON document typed by the `CharacterData` interface; every field is optional and the interface has an index signature so unknown keys round-trip. The frontend mirrors it in `dnd_vtt_frontend/src/app/core/models/character.model.ts`. Values from real columns (`id`, `user_id`, `name`, `race`, `class`, `level`, `campaign_id`, `creation_status`, `draft_step`, `created_at`, `updated_at`) are layered onto the object when read (`deserialize`) and removed again before writing (`CHARACTER_COLUMN_KEYS`), so they are never persisted inside the blob.

| Group | Keys |
|---|---|
| Identity | `subclass`, `background`, `enabled_sources` (content source codes; v019 back-filled `["XPHB"]`, or `["XPHB","EFA"]` for Artificers) |
| Abilities and proficiencies | `ability_scores` (`strength` … `charisma`), `skills`, `expertise` (maps of name → boolean) |
| HP and combat | `max_hp`, `max_hp_overridden`, `current_hp`, `temp_hp`, `hit_dice_used`, `hit_dice_total`, `death_saves` (`successes`, `failures`), `conditions`, `heroic_inspiration`, `armor_class`, `speed`, `darkvision_ft` |
| Inventory | `equipment` (array of `EquipmentEntryData`: `itemIndex`, `name`, `instanceId`, `baseItemIndex`, `quantity`, `equipped`, `attuned`, `chargesUsed`, `origin`, ...), `attuned_items`, `replicated_items`, `pact_weapon`, `inventory_version`, `currency` (`cp`, `sp`, `ep`, `gp`, `pp`). The authoritative item rows live in `inventory_instances`; the blob copy is refreshed by `InventoryService.decorate` on write |
| Spells | `spells` (`SpellEntryData`), `granted_spells`, `spell_choices`, `spell_slots_used`, `spell_slot_uses` (per pool and level), `spell_free_cast_uses`, `active_concentration` |
| Class data | `classes` (array of `ClassEntryData`: `name`, `level`, `subclass`, `choices`, `spells`, ...), `resource_uses` |
| Flavor | `personality_traits`, `ideals`, `bonds`, `flaws`, `notes` |
| Look | `avatar_url`, `portrait_seed`, `avatar_recipe`, `portrait_image`, `token_border`, `portrait_use_token` |

Validation: only the typed fields of `CharacterBodyDto` are checked on write (`ValidateOnlyPipe`); the rest passes through. See [api/characters.md](api/characters.md).

## Campaign `data` blob

`campaigns.data` is typed by `CampaignData`: `allowed_sources?: string[]` plus unknown keys that round-trip. v019 set `allowed_sources` to `["XPHB"]` on existing campaigns.
